## Canonical temporary paths

Windows and both macOS jobs stop in the offline Python tests, before compiling
the application. `verify_modules` correctly resolves the package root before
invoking the bundle executable. Its test compared that canonical command with
the unnormalized temporary-directory spelling:

- Windows: `C:\Users\RUNNER~1` aliases `C:\Users\runneradmin`.
- macOS: `/var/folders/...` aliases `/private/var/folders/...`.

The assertion now constructs its expectation from the resolved stage root.
The same test also receives `lib/..`, so every host exercises a noncanonical
spelling without requiring permission to create symlinks. That added case
reproduces the original assertion locally before the correction; afterward
both spellings pass. The production module verifier is unchanged.

## Installed Linux platform

Linux builds and passes all five CTest suites in this run: 282 reported checks,
267 passed, 15 skipped for unavailable optional codecs/camera fixtures/native
recognition packs, and no failures/errors. This includes all 30 new sharpening
reference cases under Qt 6.8.3. The installed version check then aborts with
status 134 because Qt deployment shipped XCB but the shell selected offscreen.

The installed check now selects `QT_QPA_PLATFORM=xcb` and runs both the version
and PNG-decoding commands through `xvfb-run -a`. Linux CI explicitly installs
`xvfb` and `xauth`. These are runner dependencies; no testing-only Qt plugin is
added to the application package. macOS keeps Cocoa and invokes its bundle
directly. CTest still uses offscreen from the build SDK.

The same SDK plugin/library environment variables are removed before installed
checks. Version output, image JSON/stderr and module diagnostics remain
separate, and wrapped failures preserve their original exit statuses.
