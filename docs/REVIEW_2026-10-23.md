# Critical review — 23 October 2026

Windows 11, C++20 Release, Qt 6.11.2, GCC 16.2.0. This review covers the current source, optional recognition tools, local native/offscreen tests and the shipped Windows folder. It does not establish full correctness on every desktop or image format.

## Fixed defects

- **P2 — incorrect recognition restart domain:** OCR/QR dialogs still checked the image-codec folder after tool storage was separated. A codec-folder change incorrectly blocked recognition, while a tool-folder change reached the later lease check. Both entry and restart now use the tool domain; native integration verifies successful recognition with only codec storage pending and a restart prompt with tool storage pending.
- **P2 — expensive RAW previews:** the preview suffix list omitted RAW formats such as DCR, K25 and RWZ. Those could reach the full image decoder for a thumbnail. Codec descriptions and previews now share the classification. Embedded JPEGs use size-aware decoding rather than full-size decoding followed by scaling; source pixels and full RAW development are unchanged.
- **P2 — cancelled thumbnail backlog:** every request previously allocated a future/watcher, even when thousands of requests became obsolete before GUI completion events ran. A pending queue now dispatches at most two jobs, and cancellation drops queued work immediately. Active third-party decoders still finish their current read. A 2,000-request burst checks bounded watchers, newest-generation delivery and reentrant cancellation.
- **P2 — native archive privacy:** Linux/macOS packaging now excludes app-local personal tool stores at the supported default locations. A synthetic archive test verifies both installation layouts and preservation of their original files; this is not a native OS execution test.

- **P2 — transient Windows directory locks:** one native run failed while publishing a completed portable profile. A forced Windows directory sharing lock reproduces a rename denial. Profile/extension/tool staging commits now allow up to 200 ms of cancellable retries, without replacing occupied destinations; permanent failures still return an error. Tests release a real handle during the retry, retain it until failure, cancel the commit and preserve an existing target. This verifies handling of the lock condition; it does not prove which external process caused the original intermittent failure.

- **P1 — recursive portable import:** placing the portable application inside a custom extension folder could copy the new staging directory back into itself. The import now rejects both logical and canonical containment before copying that folder. Originals remain intact. Case comparisons follow the host OS; junctions are rejected during storage copying.
- **P2 — file changes during decoding:** the document cache previously stored the decoded image against a revision captured only before reading. A concurrent rewrite could mix image/metadata revisions. Successful reads now compare the revision again and reject a changed input without replacing the current document or populating the cache. Preview decoding also checks before retaining a result.
- **P2 — HTTPS download redirects:** the old same-origin policy rejected a legitimate GitHub-to-download-host redirect. Catalogs and packages now allow at most five HTTPS redirects while blocking an HTTPS-to-HTTP downgrade. The original catalog URL remains the base for relative package names. A separate Qt HEAD probe reproduced error 11 with the old policy and HTTP 200 at codeload.github.com with the new policy. No package was uploaded or installed by this probe. Policy semantics: [Qt network redirect policies](https://doc.qt.io/qt-6/qnetworkrequest.html#RedirectPolicy-enum). The project's own hosted catalog still needs a test after publication.
- **P2 — navigation while loading:** next/previous commands now queue during animation/page decoding as well as initial file loading. Toolbar commands reach the same queue instead of being discarded by the generic busy guard. Editing, saving and modal operations retain their exclusive state.
- **P2 — background task failures:** unexpected exceptions in extension installation/folder tasks and recognition preparation are converted into dialog errors. A late preparation cancellation consistently reports cancellation. A duplicate recognition start is guarded.
- **P2 — portable tool-pack paths:** the manifest entry point must match an actual file with the same case, preventing a package that installs on Windows but cannot locate its executable/data on a case-sensitive filesystem.
- **P3 — misleading installation status:** updating a disabled tool no longer claims that it is immediately available; its disabled state remains preserved.

## Measured changes

Repeated painting now has an optional **32 MiB per-view raster cache**, covering the fitted image and background only. Selection, grid and information overlays remain separate. The first presentation remains direct; another large repaint creates the raster. Small selection strips never trigger an expensive full-image cache build. Source/zoom/origin/viewport/DPI/background/interpolation changes invalidate it. Unsupported transforms, floating-point sources, oversized surfaces and non-opaque backgrounds use the existing renderer. Setting the image cache budget to zero also disables this display cache.

The source image, editing precision and save/export pixels are unchanged. Pixel comparisons cover transparency, arbitrary 16-bit values, grayscale, floating-point fallback, interpolation, background changes, overlays, zoom, resize and source replacement at 100%, 125%, 150% and 200% scaling.

Local component timings in milliseconds, median; warm filesystem. The two repaint variants are measured in the same process with the display cache disabled/enabled. These are not process startup or whole-application speedup factors.

The Windows revision path reuses the native handle's size, identity and high-resolution timestamps instead of requesting them again through QFileInfo. POSIX uses its existing stat snapshot. Missing/unsupported native information retains the QFileInfo fallback. Cached reads, thumbnail validation and metadata indexing benefit; ordinary directory enumeration is unchanged.

First painting in the same-run control: 8-bit 3.03 / 2.94 ms and 16-bit 12.07 / 11.54 ms. These small differences fluctuate. Full decoding remains approximately 349.53 ms for the 24 MP JPEG and 342.85 ms for PNG in this run. The 10,000-entry index is 52.71 ms with all supported suffixes; no further index speedup is claimed.

Local raw reports: `tests/output/review-2026-10-23-after-final.json`, `review-2026-10-23-interaction-controls.json` and `review-2026-10-23-display-cache.json` (the latter contains the previous file-revision implementation). Temporary measurement reports are intentionally excluded from source/runtime archives. Runs performed alongside tests were discarded for performance conclusions. Release benchmarks now validate decoded fixtures/index counts even with NDEBUG; Q_ASSERT alone would not have checked them in Release builds.

## Follow-up: reported fullscreen flicker and fitted-image overflow

The previous synchronous cover lifetime did not account for Qt's queued layout/backing-store events; DwmFlush only waits for updates already submitted to the compositor. The cover now remains through those events, a fence for the completed frame and a final queued geometry check, including visible children, with bounded cleanup. The first latency optimization used GdiFlush without waiting for the new cover to be presented; the subsequent user report exposed the remaining race. A single initial DwmFlush fence now precedes native owner resizing, and the original DWM transition setting is restored under cover before the final fence. Paints remain limited to geometry changes and repeated frame-interval waits remain removed. The extra initial fence has a latency cost; local timing and the remaining GPU-specific limits are documented in PERFORMANCE.md. Rapid toggles replace pending transitions and owner destruction cancels their timers. Its own DWM transitions and Windows 11 rounded corners are disabled.

A further user report exposed a separate first-paint race: an instrumented native run observed two owner resizes while the Qt cover had not received a paint event, even though DwmFlush succeeded. The replacement uses UpdateLayeredWindow with an opaque native snapshot uploaded before showing the cover. The regression now also attempts to sample actual screen pixels while the owner has changed colour/size and no Qt events have been processed. The current local desktop denies pixel readback, which is reported as a warning; this assertion is not counted as visually verified here. Both presentation fences remain; no fixed sleeps were added. The public native runner includes this transition regression at each of its four DPI scales.

The editable zoom control also reapplied its rounded display value on confirmation/focus changes and could turn an automatic fit into a fixed zoom. Only modified user input is committed; Escape clears that modification before focus changes. Window/LargeOnly fitting uses the actual viewport, and fullscreen exit restores fitting after the normal window layout. Expanded native regressions use a 20,003-pixel panorama, visible/hidden previews, keyboard/wheel folder changes and 100/125/150/200 percent scaling. GPU/driver-specific visual validation remains separate from these checks.

## Maintenance follow-up

Recognition input preparation now lives in a UI-independent core function with direct checks for selection, alpha flattening, source preservation, cancellation and overwrite/path rejection. Architecture and development guides document ownership, thread boundaries, persistent compatibility and extension contracts. `scripts/validate.py` makes the previously local native regressions reproducible and emits a failure-aware summary; tests cover subprocess failure, timeout and the DPI/asset plan. Windows 10 CI shares that runner. Normal Windows CI now builds the bundled tool packs before deployment, fixing a missing prerequisite on a clean checkout. Hosted CI execution remains pending; local validation does not prove remote runner behavior.

## Remaining work, in priority order

1. **P1 — native platform validation:** Windows 10, Linux and macOS runs remain outstanding. Wayland global screenshots still lack the portal implementation. Monitor-profile accuracy, real HDR displays and further RAW variants require native reference checks.
2. **P2 — first decode and navigation scheduling:** codec/RAW development remains expensive. A separate load coordinator with directional prefetch and cancellation is the next substantial performance step. It must avoid duplicate foreground/background decodes, evicting useful previous images, network-file stalls and uncontrolled memory growth. Merely starting more workers can make browsing slower.
3. **P2 — memory accounting:** document/preview/display caches and undo are bounded separately; active decoders, display conversion, batch work and encoder buffers do not share a global RAM budget. The 96 MiB per-document retention ceiling also prevents caching many full-resolution 16-bit RAWs, even with a larger configured total cache.
4. **P2 — manager responsiveness:** legacy Qt-format packages still use buffered JSON/base64 parsing and synchronous installation phases. Large such packages should move fully to cancellable workers, following the streamed function-tool installer. This affects extension management rather than normal viewing.
5. **P2 — large catalogs and file operations:** ratings/metadata still use JSON snapshots. Very large collections and long-term journals need indexed storage and controlled migration. File hashes and transactional backups deliberately consume I/O; they should not be removed for faster-looking benchmarks.
6. **P2 — package and recognition coverage:** real integration fixtures cover QR, Code 39 and English OCR; difficult photographs, other barcode families and Japanese/Korean recognition accuracy need more samples. Hosted catalogs need validation after the user publishes them. Native multi-architecture tool assets should include architecture in their filenames before offering more platforms.
7. **P3 — structure and distribution:** MainWindow still coordinates too many loading, saving and file-management paths. Extracting these controllers will make further performance work safer. The viewer portion remains roughly 155 MB; bundled recognition adds about 24 MB. Meaningful further viewer size reductions need optional format packs or a tested Qt/ICU build. UI micro-optimizations do not remove those dependencies.

## Verification

The updated Windows suites contain **154 functional, 13 quality, 12 storage and 17 extension checks**, including setup/cleanup and data-driven cases, with no skips in the prepared build. They include the five pinned RAW files, ICC/precision checks and the new storage/read-race/render/navigation regressions. PSD composite fixtures cover raw/RLE RGB at 8 and 16 bits plus truncated data; real layered Photoshop/PSB/CMYK documents still need coverage. The same suites are also run against the deployed runtime with SDK directories removed from PATH. Native window/tool tests and the additional display/read-race checks are run separately; four scaling levels have pixel comparisons. Twenty-four Python checks validate packaging, SDK handling, translations and generated file associations. Final source/runtime archives and the seven optional packs are verified against their manifests and SHA-256 sums.
