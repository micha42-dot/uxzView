## Evidence and causes

The inspected [Desktop builds run](https://github.com/micha42-dot/uxzView/actions/runs/40201700693)
uses commit `29aef5e20bb12e40116f5b4d32043679c0f5fd69`. Public job metadata confirms
that Windows fails in Python tests, Linux in compilation, and both macOS jobs in
CTest. The public macOS artifacts were downloaded through nightly.link because
direct authenticated log downloads were unavailable.

- **Python release fixtures:** `BundledToolsTests.setUp()` used `tests/output`
  without creating it. Offline CI runs before CMake, which otherwise creates
  that directory. `ReleaseRuntimeTests` created its parent, but also put fixtures
  in the source tree. Both now use Python's platform temporary directory with
  `addCleanup`, including cleanup after failed setup. Other Python test classes
  already create their chosen parents; their fixtures were left unchanged.
- **Exiv2:** two `!image` checks assumed a smart pointer with a boolean operator.
  Exiv2 0.27 can return `std::auto_ptr`; `.get() == nullptr` works with it and
  newer `std::unique_ptr`. The existing version-specific I/O paths and metadata
  transformations are unchanged. Other Exiv2 factory calls were inspected; no
  further incompatible boolean checks were found.
- **Save-as:** the Intel artifact records a watchdog timeout in
  `saveAsUndoKeepsNewDestination`. This test is intended to create a new file,
  and its original target is not explicitly created elsewhere. Its timer could
  repeatedly select a file and queue `accept()` while the dialog remained
  visible, including during nested event loops. The supplied stack trace shows
  an existing selected file triggering Qt's overwrite prompt; the archived text
  does not identify that selected path. The precise race is therefore not
  established. The test now creates a separate temporary directory for each
  invocation, asserts that its destination is absent, writes the Qt file-name
  editor explicitly and queues acceptance exactly once. Unexpected message or
  modal dialogs are rejected and reported. A ten-second test-local deadline
  cancels stalled dialogs rather than waiting for the five-minute watchdog.
  Assertions check the saved rotated image, Undo's original pixels, the retained
  destination, modified state, unchanged saved output and unchanged source.
  The selection-export test had the same repeated-submit pattern and now also
  selects the editor and submits once. Native dialogs are disabled only within
  these tests and the previous attribute is restored. Application overwrite
  prompts and application save code are unchanged.
- **Additional macOS About failure:** the Apple Silicon artifact reports
  `keyboardHelpAndBranding` failing at `brandCorrect`. Qt 6.8.3 explicitly shows
  its About box modelessly on macOS, whereas this test assumed a blocking modal
  dialog and asserted immediately. The test now polls visible message windows,
  captures their text, closes the About box and waits for observation before
  checking branding. This matches the
  [Qt 6.8.3 implementation](https://github.com/qt/qtbase/blob/v6.8.3/src/widgets/dialogs/qmessagebox.cpp).
- **macOS workflow suite remains undiagnosed:** neither downloaded artifact
  contains `workflow-test-results.txt` or its XML counterpart. An exit code and
  duration do not establish a cause. No speculative application/workflow-test
  changes were made. The same 48 workflow checks pass locally on Windows; this
  does not establish their macOS result.

## CI diagnostics

CMake already registers all five suites and writes complete QtTest text and
JUnit reports. These file loggers leave CTest's captured stdout mostly empty.
The workflow previously uploaded only the main and quality results on Unix,
discarding the workflow-suite evidence needed to diagnose the failure.

`report_test_logs.py` now prints all retained suite text reports and CTest's
`Testing/Temporary/LastTest.log`. Desktop CI calls it on failure and always
uploads all `*test-results.*` and CTest logs. Windows' build helper uses the same
reporter on test failure. Two offline tests cover every suite, partial/invalid
UTF-8 crash output, absent build directories and exclusion of unrelated files.
Linux and both macOS jobs now also run the Python tests with Python 3.14. The
four existing build targets, CPU selections, Qt 6.8.3 configuration, tests,
timeouts and install/smoke/package steps are retained.
