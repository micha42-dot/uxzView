## Linux: Exiv2 0.27 thumbnail buffer

The supplied Linux compiler log identifies
`selectionExportRemovesOriginalExifThumbnail` in `tests/test_ixview.cpp`:

```text
error: 'class Exiv2::DataBuf' has no member named 'size'; did you mean 'size_'?
```

The assertion used the Exiv2 0.28 `size()` accessor unconditionally. It now uses
the existing version gate, reading `size_` on 0.27 and `size()` on newer Exiv2.
Both paths still assert that the exported selection contains no original EXIF
thumbnail. No test or metadata feature is disabled and distro libraries remain
supported. This fixes the reported compile error; local Windows uses newer
Exiv2 and cannot establish the complete Linux result.

## macOS: message titles are deliberately absent

Both downloaded, hash-verified macOS artifacts report the same failure in
`saveKeepsTargetChangedDuringLossWarning`: the test never observes its expected
warning, so never rewrites the target at the intended point. The test identifies
the warning by its window title, but
[Qt 6.8.3 QMessageBox::setWindowTitle](https://github.com/qt/qtbase/blob/v6.8.3/src/widgets/dialogs/qmessagebox.cpp)
deliberately ignores titles on macOS, including the widget implementation used
in offscreen tests.

The test now recognizes the exact export-loss text, Warning icon and Yes/Cancel
buttons. A second data row clears message titles on every host, exercising the
previous failure outside macOS too. Submission remains one-shot; an explicit
deadline and missing-editor failure prevent hidden dialog stalls. Assertions
verify the externally rewritten target's hash/dimensions, unchanged source hash
and original document path after the failed save. Production save behavior and
overwrite protection are unchanged.

Three different follow-up failures remain in that uploaded run:

- **Windows preview fixture:** `previewsReuseOnlyEligibleCachedOriginals(static-png)`
  returns the synthetic cached original after the fixture rewrite. The failing
  report does not contain native revision fields; it does not establish a
  general decoder or content-integrity fix. The fixture changed dimensions by
  only one pixel, which need not change compressed PNG byte length. Rapid
  same-size writes can also share a filesystem timestamp tick. This test now
  uses a larger replacement, explicitly checks that encoded byte length and
  source revision differ, then checks the new red preview. It adds no delay or
  retry. The separate same-size/preserved-mtime rewrite regression remains and
  passes locally; metadata-based revisions are not content hashes.
- **Linux folder fixture:** the new artifact shows identical file-list ordering
  but a different `latest` file. The fixture assigns mtime while small writes
  remain buffered. In
  [Qt 6.8.3 QFileDevice::setFileTime](https://github.com/qt/qtbase/blob/v6.8.3/src/corelib/io/qfiledevice.cpp)
  the setter does not flush those writes; a subsequent Unix write on close can
  replace the assigned mtime. The fixture now flushes successfully first, sets
  mtime, closes the file and asserts the intended timestamp before testing any
  sorting/latest result. Enumeration and sorting production code are unchanged.
- **macOS package startup:** the supplied smoke log says the `offscreen` Qt
  platform is unavailable and `cocoa` is installed. The workflow forced
  `QT_QPA_PLATFORM=offscreen` after removing SDK plugin paths, so the packaged
  app aborts before `--version`. The macOS smoke check now uses its bundled
  native Cocoa platform. Linux retains its offscreen check. No test-only
  platform plugin is added to the macOS package.

Installed `--version` output and image-probe stderr are now retained in
`installed-version.log` and `installed-image-probe.log`, printed on failure and
uploaded even after an abort. JSON stays separate from stderr, and the original
process failure status is preserved. The offline reporter regression includes
