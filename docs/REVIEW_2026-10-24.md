# Follow-up review — 2026-10-24

This pass examines document navigation, modal file operations, thumbnail decoding, slideshow scheduling and export buffers. It is a focused source review with executable regressions, not a claim that every feature or platform is defect-free. The previous fullscreen correction remains in place.

## Reproduced defects

| Priority | Trigger and previous result | Correction |
| --- | --- | --- |
| P1 | Another editor rewrites a file while the Rename dialog is open. After renaming, the viewer retained the old pixels but adopted the new file revision, weakening subsequent conflict detection. | Compare the source revision in the worker immediately before the file operation. Reload an unmodified document when the source changed; retain the existing conflict handling for edited documents. |
| P2 | A file-open request waits behind a modal dialog. A newer choice opens after the dialog closes, then the old 50 ms timer replaces it. | An accepted request cancels the older deferred request. Explicit choices cancel old navigation steps; delayed navigation consumes live pending state, and animation/slideshow ticks defer to an explicit pending open. |
| P2 | A portrait JPEG carries EXIF orientation 6 or 8 and is shown in a wide thumbnail. Scaling before rotation used the final bounds, decoded too few pixels, then enlarged the result. | Transpose decoder bounds for 90/270-degree orientations before decoding. The fixture's original luminance error against a full-decode reference was 61.91/255. |

All three cases failed against the previous implementation in `build/deep-review-before.txt`. The thumbnail fixture carries an explicit minimal EXIF block; a writer-side rotation alone does not establish that the fixture contains orientation metadata.

## Performance changes

- Random slideshow selection previously rebuilt a membership hash and filtered the remaining paths for every image, then removed a random element from the middle of a list. It now shuffles once per round and pops from the end. Directory changes still filter removed files; new arrivals join the next round. The shared directory snapshot avoids rebuilding membership for an unchanged folder.
- Exports that require no metadata rewriting now write directly into the atomic `QSaveFile` staging file. They no longer retain an additional byte array containing the entire encoded output. Metadata rewriting retains its buffered path, and pixels, ICC, DPI, alpha conversion and atomic commit behavior remain covered by tests. This does not remove codec-internal buffers or establish a global memory limit.

The slideshow benchmark uses five alternating samples in one process: 1,000 selections from 10,000 unchanged paths, comparing the previous algorithm with the controller. It excludes reading and displaying images. Run `ixview_benchmarks <report.json> --profile-slideshow -platform offscreen`; its result must not be presented as a general viewer speedup.

On this Windows 11 release build, median selection time fell from **1,660.95 ms to 1.01 ms** for that batch of 1,000 choices. The five samples range from 1,634.56–2,009.65 ms before and 0.82–1.08 ms after. Local measurement: `tests/output/slideshow-review-2026-10-24.json`. The previous-algorithm reference even excludes its initial list preparation from timing; the current controller includes round setup. No end-to-end browsing speed or export memory measurement is inferred.

They cover deferred requests, folder navigation, rotated thumbnails, changing slideshow directories, rename conflicts and export integrity. The public validation runner and SDK-free portable checks include this suite. Keeping it separate avoids adding these cases to the already large main test translation unit.

## Remaining work

1. File revision checks and actual filesystem mutations are not a single atomic compare-and-swap across unrelated editors. The fixed dialog-time hole is covered; simultaneous writes during the operation still require a stronger conflict/locking design. Journal crash recovery also remains incomplete.
2. Loading and navigation still share substantial state in `MainWindow`. A coordinator should own pending intents, document installation and cancellation before adding directional prefetch. Callback reentrancy and foreground/background decode duplication need particular attention.
3. Large RAW decoding and aggregate RAM remain the main performance risks. Separate cache/undo/batch limits do not bound all active buffers. Metadata-bearing exports still require a complete encoded buffer.
4. Catalog writes and some format-package installation work remain synchronous. Large catalogs and extension packages need measured worker-backed or indexed designs rather than additional GUI-thread work.
5. Native Windows 10/Linux/macOS, real HDR/multiple-monitor color behavior and broader RAW/recognition samples remain unverified. Native geometry/state tests do not prove absence of fullscreen flicker on every GPU; desktop pixel-readback limitations are reported separately.
