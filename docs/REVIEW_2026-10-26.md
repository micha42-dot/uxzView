## Status updates without filesystem polling

`MainWindow::updateStatus()` queried the source file's last-write time on every
zoom and selection update. This adds synchronous filesystem work to frequent
GUI events and can be expensive on remote or slow storage.

`ImageDocument::sourceModified` now records the source last-write time when
`CodecRegistry::read()` succeeds. The image-load cache's existing revision
checks still reject files changed during decoding. The status bar formats the
stored timestamp; it does not query the filesystem when zoom/selection changes.
It describes the loaded revision, consistently with stored dimensions and file
bytes. External modifications become visible after reopening/reloading the
image, rather than mixing a newer disk timestamp with older displayed pixels.

Save and rename/move workers now return source revision, timestamp and file
size together. A shared private helper installs these fields in the document
and its applicable Undo/Redo history. This moves the existing post-operation
attribute queries off the GUI thread and keeps Save-as/Undo associated with
the new destination. Copying or exporting a selection leaves the active
document's source state intact.

These changes do not make filesystem checks and mutations atomic against other
programs. They reduce GUI-thread I/O; no new general speedup percentage or
network-drive timing is claimed.

## Bounded first-image diagnostics

`scripts/measure_first_open.py` runs the benchmark in fresh processes, with a
40-second external deadline, and stops on the first failure. Each process
opens the selected image three times with image caches cleared. The runner
retains complete logs, partial JSON, exit/timeout status and the last emitted
checkpoint. Old result files cannot turn a failed/no-output run into success;
missing, negative and nonfinite timing metrics are rejected.

Benchmark checkpoints bracket window creation, initial visibility, individual
opens and window destruction. Optional image-load tracing brackets worker
decode/preparation and GUI document installation without logging image paths.
The benchmark window is shown without automatic activation/focus capture;
normal application windows keep their existing behavior. The runner enables
tracing only in its child processes. Logs/commands can contain local paths and
remain generated output under `build`, outside public source selection.

```powershell
python -B scripts/measure_first_open.py --platform windows --samples 3 --output build/first-open-diagnostics.json
# Default offscreen mode:
python -B scripts/measure_first_open.py --image example.jpg --samples 3
```

Six fresh native Windows processes completed successfully, covering the PNG
smoke fixture and the README JPEG, three processes per image. Evidence:
`build/second-load-native-diagnostics.json`, its per-process reports/logs and
`build/second-load-native-diagnostics.log`. All measured paints completed.
The original isolated native timeout was not reproduced and its cause remains
unknown. Added diagnostics improve evidence for a recurrence; they are not
proof that every intermittent hang is fixed.

These are traced diagnostic runs, with a nonactivating benchmark window. Their
timings must not be compared as a controlled speedup against the earlier
untraced/activating benchmark. Pixel drawing still does not prove final
compositor presentation.
